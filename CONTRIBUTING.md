# Contributing to Vex Core

Contributions are welcome while Vex is in pre-alpha development.

Read the complete Vex-specific contribution workflow in
[`docs/vex/CONTRIBUTING.md`](docs/vex/CONTRIBUTING.md).

Before opening a code pull request:

1. create or identify a focused tracking issue in
   [`VexBrowser/vex-browser`](https://github.com/VexBrowser/vex-browser/issues);
2. read [`AGENTS.md`](AGENTS.md) and the applicable engineering rules under
   [`docs/vex/`](docs/vex/README.md);
3. investigate existing Brave and Chromium foundations;
4. keep the change isolated and minimize inherited-file edits;
5. build and validate the change on the Ubuntu reference environment;
6. complete the repository pull-request template honestly.

Inherited Brave and Chromium documentation remains authoritative for their code
style, build tooling, tests, and subsystem-specific practices. Brave issue
trackers, support channels, release processes, and organizational permissions
do not represent Vex.

Do not report security vulnerabilities publicly. Follow
[`SECURITY.md`](SECURITY.md).

Vex-specific source contributions are intended to remain under MPL-2.0 unless
explicitly stated otherwise. Contribution rights do not grant permission to use
the proprietary Vex name, logos, icons, wordmarks, or visual identity. See
[`NOTICE`](NOTICE) and [`TRADEMARKS.md`](TRADEMARKS.md).
